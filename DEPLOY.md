# ShieldScan — Production Deployment Guide

**Target:** Oracle Cloud Always Free (ARM) or any Ubuntu 22.04 VPS (Hetzner, DigitalOcean, OVH)  
**Cost:** €0/month on Oracle Cloud + free DuckDNS subdomain  
**Time:** ~30 minutes end-to-end

---

## Overview

```
Internet → DuckDNS (shieldscan.duckdns.org) → Oracle VM → Nginx (443) → FastAPI (8000)
                                                         ↓
                                               PostgreSQL + ChromaDB (internal Docker network)
```

---

## Part 1 — Get a free domain (DuckDNS)

1. Go to **https://www.duckdns.org** → Log in with Google
2. Create a subdomain, e.g. `shieldscan` → you get `shieldscan.duckdns.org`
3. Note your **token** (shown on the dashboard) — needed for SSL renewal
4. Leave the IP blank for now — you'll fill it after creating the VM

---

## Part 2 — Create Oracle Cloud VM (Always Free)

1. Sign up at **https://cloud.oracle.com** (credit card needed but never charged)
2. Go to **Compute → Instances → Create Instance**
3. Configure:
   - **Name:** shieldscan-prod
   - **Shape:** `VM.Standard.A1.Flex` ← ARM, Always Free
   - **OCPU:** 4 | **RAM:** 24 GB
   - **Image:** Ubuntu 22.04 (Minimal)
   - **Boot volume:** 50 GB (free up to 200 GB total)
   - **SSH keys:** Upload your public key (`~/.ssh/id_rsa.pub`)
4. Click **Create** — VM is ready in ~2 minutes
5. Note the **Public IP address**

### Open firewall ports (Oracle Cloud console)

Oracle blocks ports by default — you must open them in two places:

**In Oracle Cloud console:**
- Go to **Networking → Virtual Cloud Networks → your VCN → Security Lists → Default Security List**
- Add Ingress rules:
  | Protocol | Port | Source CIDR |
  |----------|------|-------------|
  | TCP | 80 | 0.0.0.0/0 |
  | TCP | 443 | 0.0.0.0/0 |

**On the VM itself** (SSH in first):
```bash
sudo iptables -I INPUT -p tcp --dport 80 -j ACCEPT
sudo iptables -I INPUT -p tcp --dport 443 -j ACCEPT
sudo netfilter-persistent save
# OR:
sudo ufw allow 80 && sudo ufw allow 443
```

---

## Part 3 — Set your DuckDNS IP

1. Back on **duckdns.org**, enter your Oracle VM's public IP → click **Update IP**
2. Wait 2–3 minutes for DNS propagation
3. Verify: `dig shieldscan.duckdns.org` should return your VM IP

---

## Part 4 — Deploy ShieldScan

SSH into your Oracle VM:
```bash
ssh ubuntu@YOUR_ORACLE_IP
```

Run the deploy script:
```bash
# Clone the repo
git clone https://github.com/YOUR_ORG/shieldscan.git /opt/shieldscan
cd /opt/shieldscan

# Run deploy (prompts for Groq key + domain)
sudo bash deploy.sh
```

The script will:
- Install Docker
- Generate JWT + encryption keys automatically
- Ask for your Groq API key (free at [console.groq.com](https://console.groq.com))
- Ask for your DuckDNS domain
- Build and start all containers
- Run Alembic migrations automatically on startup

**Estimated build time:** 5–8 minutes (Trivy download is the slow part)

---

## Part 5 — Add HTTPS with Let's Encrypt

Once `deploy.sh` completes and your domain resolves correctly:

```bash
sudo bash setup-ssl.sh
```

This will:
- Issue a Let's Encrypt certificate for your DuckDNS domain
- Configure Nginx for HTTPS
- Set up auto-renewal (runs every 1st and 15th of the month)

## Part 6 — Verify it's working

```bash
# Health check
curl https://shieldscan.duckdns.org/health

# Version
curl https://shieldscan.duckdns.org/api/version

# Check all containers are running
docker compose ps
```

Expected `/health` response:
```json
{"status": "ok", "database": "ok", "ai_provider": "groq"}
```


## Useful commands

```bash
# View logs
docker compose logs -f api          # FastAPI
docker compose logs -f nginx        # Nginx
docker compose logs -f db           # PostgreSQL

# Run Alembic manually (migrations auto-run on startup, but manual override)
docker compose exec api alembic upgrade head

# Access PostgreSQL
docker compose exec db psql -U shieldscan -d shieldscan

# Restart individual services
docker compose restart api
docker compose restart nginx

# Full restart
docker compose -f docker-compose.yml -f docker-compose.prod.yml down
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d

# Check disk usage
docker system df
```

## Environment variables reference

All variables are in `app/backend/.env`. The `deploy.sh` script creates this from `.env.example` and auto-generates secrets.

**Required (auto-generated by deploy.sh):**
| Variable | Description |
|----------|-------------|
| `JWT_SECRET_KEY` | JWT signing key (≥ 32 chars) |
| `AWS_ENCRYPTION_KEY` | Fernet key for encrypting stored AWS credentials |

**Required (you provide):**
| Variable | Description |
|----------|-------------|
| `GROQ_API_KEY` | Free AI — [console.groq.com](https://console.groq.com) |
| `CORS_ALLOWED_ORIGINS` | Your DuckDNS domain in JSON array |

**Optional:**
| Variable | Description |
|----------|-------------|
| `ADMIN_PASSWORD` | Auto-generated. Check `deploy.sh` output. |
| `EMAIL_USER` / `EMAIL_PASSWORD` | Gmail App Password for email verification |
| `ANTHROPIC_API_KEY` | Switch to Claude for AI (set `AI_PROVIDER=claude`) |

## Migrating from SQLite to PostgreSQL

If you were running locally with SQLite and have existing data:

```bash
# On your local machine — export data to SQL
cd app
python -c "
import sqlite3, json
conn = sqlite3.connect('shieldscan.db')
# Export each table as INSERT statements
for table in ['users', 'scans', 'findings']:
    cursor = conn.execute(f'SELECT * FROM {table}')
    cols = [d[0] for d in cursor.description]
    for row in cursor.fetchall():
        print(f'-- {table}: {dict(zip(cols, row))}')
"
```

For student/demo usage there's typically no need to migrate — just start fresh on the server. All CSPM findings are regenerated on each scan.

## Architecture on Oracle Cloud

```
┌─────────────────────────────────────────────────────┐
│  Oracle Cloud VM (ARM, 4 OCPU, 24GB RAM)            │
│                                                     │
│  ┌─────────────────┐         ┌──────────────────┐   │
│  │    nginx:443    │────────▶│   api:8000       │   │
│  │  Let's Encrypt  │         │   FastAPI        │   │
│  │  Rate limiting  │         │   2-4 workers    │   │
│  └─────────────────┘         └────────┬─────────┘   │
│                                       │             │
│              ┌────────────────────────┼──────────┐  │
│              │     Internal network   │          │  │
│              │  ┌──────────────────┐  │          │  │
│              │  │  db:5432         │◀─┤          │  │
│              │  │  PostgreSQL 16   │  │          │  │
│              │  └──────────────────┘  │          │  │
│              │  ┌──────────────────┐  │          │  │
│              │  │  chromadb:8000   │◀─┘          │  │
│              │  │  Vector store    │             │  │
│              │  └──────────────────┘             │  │
│              └──────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

**Data persistence:** Docker named volumes (`postgres_data`, `chroma_data`, `trivy_cache`) survive container restarts and updates. They are stored on the VM's boot volume (50 GB by default).

## Troubleshooting

**API container keeps restarting:**
```bash
docker compose logs api --tail=100
# Look for: JWT_SECRET_KEY too short, DATABASE_URL wrong, ChromaDB unreachable
```

**Nginx returns 502 Bad Gateway:**
```bash
# API is not ready yet — check if it's still running migrations
docker compose ps api
docker compose logs api --tail=20
```

**Let's Encrypt certificate fails:**
- Make sure port 80 is open in Oracle Security List AND `ufw`
- Make sure DNS is pointing to your server IP: `dig shieldscan.duckdns.org`
- Make sure DuckDNS IP is updated

**PostgreSQL connection refused:**
```bash
# Check if postgres container is healthy
docker compose ps db
# If not healthy, check postgres logs
docker compose logs db --tail=20
```
