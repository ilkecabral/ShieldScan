The problem

Most security tools assume you already have a security team

The tools that actually work — Wiz, Orca, Prisma Cloud — start at $15,000 a year. AWS Security Hub gets you part of the way there, but you still have to interpret 200-page reports with no context. ShieldScan is for everyone else.

  • 💸
    Enterprise tools charge enterprise prices

    Wiz costs roughly $15k/year. Orca is similar. AWS Security Hub adds up fast once you leave the free tier. None of that is realistic for a student project or a two-person startup.

  • 🤯
    Audit reports that nobody reads

    Most CSPM tools dump findings into a spreadsheet and leave you to figure out what matters. ShieldScan ranks everything by risk score and tells you what to fix first.

  • 🔒
    Default AWS configs are not secure

    The AWS defaults that ship when you spin up a new account — S3 public access, no MFA, no CloudTrail — would fail a basic security audit. Most people don't find out until something goes wrong.

What it does

Everything in one scan

One scan covers your AWS configuration, your containers, your compliance posture, and your overall risk. The AI assistant explains any finding in plain English and writes the fix.

Cloud Security Posture (CSPM)

Checks your AWS account against 25 CIS Benchmark v1.5 controls. Finds open S3 buckets, root access keys, missing MFA, exposed security groups, CloudTrail gaps, and weak password policies.

How it works

Connected and scanning in under 5 minutes

You need an AWS IAM user with the SecurityAudit managed policy. That's it.

1

Create an account

Sign up with your email. No credit card. Student emails get free access permanently.

2

Connect AWS

Add your IAM access key and secret. ShieldScan encrypts them with Fernet before storing. Read-only SecurityAudit policy is all that's needed.

3

Run a scan

Click Scan. Watch each check complete in real time. Takes 60–90 seconds for a typical account.

4

Fix what matters

Read the findings ranked by risk. Use the AI assistant to get exact fix instructions. Re-scan to confirm.

Actual results from a typical AWS account

This is what you get after a scan. Each finding has a severity, the exact resource affected, and a fix. No noise, no filler.

CRITICAL Root account has active access keys
The AWS root account has active programmatic access keys. Root keys have unrestricted access to every service. A leaked root key means full account compromise.
How to fix AWS Console → Account menu → Security credentials → Access keys → Delete both keys.
HIGH SSH (port 22) open to 0.0.0.0/0
Security group sg-0abc1234 allows inbound SSH traffic from any IP. Any machine on the internet can attempt to connect to your instances.
How to fix EC2 → Security Groups → sg-0abc1234 → Inbound rules → change source from 0.0.0.0/0 to your specific IP.
MEDIUM IAM user 'devuser' has access keys but no MFA
'devuser' has active access keys but no MFA device configured. Stolen keys grant API access with no second factor.
How to fix IAM → Users → devuser → Security credentials → Assign MFA device.

AI assistant

Ask about your findings, get actual answers

The assistant runs on a locally hosted Llama 3 model with RAG (Retrieval-Augmented Generation) — your latest scan data is loaded as context at every query. So when you ask "how bad is this?" it answers about your account, not some generic scenario.

It knows which findings you have, their severity, the affected resources, and the current fix recommendations. You can ask it to write the AWS CLI commands, explain the attack path, or prioritize what to fix this week.

AI Assistant — scan #14 loaded
K
What's the worst thing in my scan right now?
AI
The root account having active access keys. If those credentials leak — from a public Git repo, a misconfigured S3 bucket, anything — someone has full control of your AWS account. No permission boundary, no recovery. Delete them now: AWS Console → Account → Security credentials → Access keys → Delete.
K
Can you write the CLI command to restrict SSH on my security group?
AI
For sg-0abc1234, run: aws ec2 revoke-security-group-ingress --group-id sg-0abc1234 --protocol tcp --port 22 --cidr 0.0.0.0/0. Then add your IP back: aws ec2 authorize-security-group-ingress --group-id sg-0abc1234 --protocol tcp --port 22 --cidr YOUR.IP.HERE/32. Replace YOUR.IP.HERE with your actual IP.

Questions

Stuff people ask before signing up

What AWS permissions does ShieldScan need?
The SecurityAudit AWS managed policy is enough. It's a read-only policy that lets ShieldScan list resources without making any changes. We never write to your account. You can verify this in the IAM console or by reading our scanner source code.
How are my AWS credentials stored?
Your access key and secret key are encrypted with AES-128 Fernet symmetric encryption before being written to the database. The encryption key lives in the server environment, not in the database itself. We do not log credentials or pass them to third-party services.
Does ShieldScan change anything in my AWS account?
No. ShieldScan only reads. It calls List*, Describe*, and Get* API endpoints. Nothing is created, modified, or deleted. The SecurityAudit policy explicitly prevents write access.
What's the difference between CSPM and CWPP?
CSPM (Cloud Security Posture Management) checks your AWS account configuration against security best practices. It finds things like open S3 buckets and missing MFA. CWPP (Cloud Workload Protection Platform) scans Docker container images for known CVEs in the software installed inside them. ShieldScan does both in the same scan.
Is this actually useful for a school project / student portfolio?
Yes. If you're running a project on AWS — even a small one — ShieldScan will find real problems. The PDF report is useful for demonstrating security awareness in a course submission or a job interview. It's also just a good habit to run before you hand over access to anyone else.
How is the risk score calculated?
An XGBoost model takes the count and severity of findings as input features and outputs a score from 0 to 100. A score of 0 means no problems found. A score of 100 means critical findings across multiple categories. The model was trained on a synthetic dataset of AWS account configurations with known risk levels.
